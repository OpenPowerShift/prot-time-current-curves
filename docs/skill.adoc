= Writing a tc-curves study from a setting report
:toc: left
:toclevels: 2
:icons: font
:source-highlighter: highlight.js

This document is written for an AI agent. You have been given a
protection setting report, or a set of relay settings, and asked to
produce a time-current coordination (TCC) study.

Read this once, then write the study. It is deliberately short: the
whole language is in the reference guide, and *most studies need about
fifteen lines of it*.

[IMPORTANT]
====
Two rules that matter more than anything else here.

. *Only write what the report says.* Every number in a study is a claim
  about a real relay. If the report does not give a TMS, do not write
  one -- the tool will tell the reader it is missing, which is the
  correct outcome. Inventing a plausible value produces a drawing that
  looks authoritative and is fiction.
. *Then run it.* `tc-curves check study.ptc` is not optional. It is a
  validator with about ninety checks, and it is faster and more
  reliable at finding your mistakes than re-reading your own output.
====

== What you are producing

A `.ptc` text file. Feed it to the tool and it draws a log-log chart of
operate time against current, with every relay's characteristic on it,
and computes the grading margins between them.

[source,bash]
----
tc-curves check  study.ptc          # every finding, and each failing grade
tc-curves report study.ptc          # the margins, pair by pair
tc-curves render study.ptc --pdf    # the sheet
----

Exit status: `0` clean, `1` a study error, `2` usage or I/O, `3` a
valid study whose *grading fails* -- which is a real answer, not a bug.
Exit `0` is not "coordinates": read every warning `check` prints. A
grade with no `margin` has no verdict (`GRADE_NOT_EVALUATED`), and one
where nothing operates at the fault is not a pass.

== The smallest study that says something

Start here. Add nothing until a question forces you to.

[source,tc]
----
system {
    voltages { MV { V = 11 kV; } }
}

faults {
    F_FEEDER_MAX { I = 6.2 kA; type = three_phase; voltage = MV; }
}

relay R_FEEDER {
    voltage  = MV;
    ct_ratio = 400/5;
    element 51 {
        function = phase_oc;
        measures = phase;
        curve    = iec.si;
        I_pickup = 480 A;
        tms      = 0.10;
    }
}

relay R_INCOMER {
    voltage  = MV;
    ct_ratio = 800/5;
    element 51 {
        function = phase_oc;
        measures = phase;
        curve    = iec.si;
        I_pickup = 800 A;
        tms      = 0.25;
    }
}

grade {
    primary = R_FEEDER:51;
    backup  = R_INCOMER:51;
    fault   = F_FEEDER_MAX;
    margin  = 0.30 s;
}

view { voltage = MV; }
----

That is a complete, valid, useful study. Everything else in this
document is an answer to a specific question the report raised.

=== What each part is for

[cols="1,3", options="header"]
|===
| Block | Why it is there

| `system` | Names the voltage levels. Needed the moment two levels
             exist, so that a fault on one can be referred to the other.
| `faults` | The currents grading is judged at. Without one there is
             nothing to compute a margin from.
| `relay`  | A physical device. Its `element`s are its settings.
| `grade`  | The question: does this pair coordinate? One per pair, with
             a `margin` (or one in `meta`) -- without it there is no verdict.
             A study with a single relay has nothing to grade, and that is fine.
| `view`   | One sheet. Left bare, it fits itself to what is drawn.
|===

== Reading a setting report

Setting reports vary. This is the mapping that holds across all of
them.

[cols="2,2,2", options="header"]
|===
| The report says | You write | Notes

| CT ratio 400/5 | `ct_ratio = 400/5;` | On the *relay*, not the element.
| Pickup / I> / Is | `I_pickup = 480 A;` | Primary amps by default.
| 1.2 x In, In = 400 A | `I_pickup = 480 A;` | Multiply it out yourself.
| Setting in secondary A | `I_pickup = 6 A_sec;` | Needs `ct_ratio`.
| TMS / TD / time dial | `tms = 0.10;` | Never guess this.
| IEC standard inverse | `curve = iec.si;` | See the curve table below.
| Definite time, 0.1 s | `curve = definite; t_delay = 100 ms;` | No `tms`. Always write the `curve`.
| Min. time of the curve | `t_floor = 100 ms;` | On an inverse stage. Never `t_delay` there.
| Added delay on an IDMT stage | -- | Not supported. Say so in your summary.
| Relay sees 50 % of the fault | `share = 50 %;` | Every percentage takes `%`.
| 50 / high-set / I>> | a second `element`, or a `stage` | Below.
| 51N / 51G / earth | `function = earth_fault;` | Measures residual `3I0`.
| 46 / negative sequence | `function = neg_seq; measures = I2;` | State the scaling.
| Grading margin 0.3 s | `margin = 0.30 s;` on the `grade` | Or in `meta`.
| Dyn11 / vector group | `transformer HV to LV { vector_group = "Dyn11"; }` | Needed for any unbalanced fault across it.
|===

=== Curves

Write the standard's name. The tool carries the constants.

[cols="1,2", options="header"]
|===
| Family | Written

| IEC 60255-151 | `iec.si`, `iec.vi`, `iec.ei`, `iec.lti`
| IEEE C37.112  | `ansi.mi`, `ansi.vi`, `ansi.ei`
| Definite time | `definite` (with `t_delay`, not `tms`)
| Vendor        | `sel.c1`, `abb.ri`, `ge.ur.mi`, and others -- see the reference
| Tabulated     | `flex_points = [(I, t), ...]` when the report gives a table
|===

If the report names a curve you cannot map, use `formula` with the
constants it gives rather than picking a near-neighbour:

[source,tc]
----
element 51 {
    function = phase_oc;
    measures = phase;
    formula  = { k = 0.14; alpha = 0.02; c = 0; };
    I_pickup = 480 A;
    tms      = 0.10;
}
----

== The decision ladder

The rows are independent: add every row that applies to your report,
and nothing for the rows that do not.

[cols="1,3,2", options="header"]
|===
| # | If the report... | ...then add

| 1 | is one voltage, phase overcurrent only | nothing. The study above is done.
| 2 | has a high-set (50) as well as a 51 | a `stages` block, <<stages>>
| 3 | has an earth-fault element | `function = earth_fault`, <<earth>>
| 4 | spans a transformer | a second voltage, a `transformer` with its vector group, <<levels>>
| 5 | gives a fault *range*, not one figure | `I_min` / `I_max`, <<ranges>>
| 6 | gives negative-sequence settings | `measures = I2` or `3I2`, <<sequence>>
| 7 | states a required clearance time, or a rating | `times` / `currents`, <<times>>
| 8 | includes a fuse or cable damage curve | a `device`, <<devices>>
| 9 | is several chains, or needs several sheets | `group` and `view`, <<sheets>>
| 10 | needs a mark or margin figure | `point` / `annotate`, <<marks>>
|===

Rows 1--4 cover most reports. Rows 5--9 are the advanced cases: use
them when the report contains the data, and not otherwise.

[#stages]
== 2. A relay with two settings that act together

A 51 with a 50 is *one element with two stages*, not two elements,
whenever they are the same protection function on the same CT. The
drawn curve is then the composite -- what the relay actually does.

[source,tc]
----
element 51 {
    function = phase_oc;
    measures = phase;
    stages {
        stage IDMT { curve = iec.si;   I_pickup = 480 A;  tms = 0.10; }
        stage HIGH { curve = definite; I_pickup = 4.5 kA; t_delay = 50 ms; }
    }
}
----

If the high-set is blocked above some current -- a common setting where
it must not see a through-fault -- say so, and mean it:

[source,tc]
----
element 51 {
    function = phase_oc;
    measures = phase;
    stages {
        stage IDMT { curve = iec.si; I_pickup = 480 A; tms = 0.10; }
        stage HIGH {
            curve    = definite;
            I_pickup = 4.5 kA;
            t_delay  = 50 ms;
            I_cutoff = 6 kA;      # the stage does not exist above this
        }
    }
}
----

`I_cutoff` is not decoration. Past it the stage does not operate, the
composite steps back onto the inverse stage, and a grade asked for
beyond it is refused rather than answered.

[#earth]
== 3. Earth fault

An earth-fault element does not measure phase current. It measures the
residual, `3I0`, and stating that is what stops it being drawn against
the wrong axis.

[source,tc]
----
element 51G {
    function = earth_fault;    # -> residual 3I0
    curve    = iec.si;
    I_pickup = 80 A;
    tms      = 0.10;
}
----

Give it its own sheet, because phase and earth currents on one axis
invite a comparison that means nothing:

[source,tc]
----
view PHASE { quantity = phase; voltage = MV; title = "Phase grading"; }
view EARTH { quantity = 3I0;   voltage = MV; title = "Earth grading"; }
----

[#levels]
== 4. Across a transformer

Declare both levels **and the transformer between them**. Each relay
says which one it is on. The turns ratio alone refers a balanced fault
correctly and nothing else, so the vector group is not optional
decoration -- write what the nameplate says.

[source,tc]
----
system {
    voltages {
        HV { V = 33 kV; }
        LV { V = 11 kV; }
    }

    transformer HV to LV {
        vector_group = "Dyn11";
    }
}

relay R_HV { voltage = HV; ct_ratio = 200/5; }   # ... its elements
relay R_LV { voltage = LV; ct_ratio = 600/5; }

view { voltage = HV; }    # everything framed in 33 kV amps
----

A delta-star transition redistributes the phase currents: an LV
phase-phase fault comes out `2/sqrt(3)` higher on the HV side than the
ratio gives, and an LV earth fault `1/sqrt(3)` lower. Both change the
margin.

[WARNING]
====
Where the windings do not settle it, the tool refuses
(`REFERRAL_NEEDS_CONNECTION`) rather than quoting the ratio: a
two-phase-earth fault needs `Z0`, and an earth fault across two earthed
stars splits by the zero-sequence impedance network. Declare the
condition as a `scenario` with figures at each level instead of asking
for the conversion. That refusal is the tool working.
====

[#ranges]
== 5. A fault range rather than a point

Setting reports usually give minimum and maximum fault levels. Give
both, and the margin is checked across the range rather than at one
convenient current. `I` is always required -- it is the current the
grade is judged at; the range is stated *around* it. Where the report
gives only a range, use the figure the report grades at, usually the
maximum, and say so in your summary.

[source,tc]
----
faults {
    F_BUS {
        type  = three_phase;
        voltage = HV;
        I     = 6.2 kA;      # the graded point
        I_min = 4.1 kA;
        I_max = 8.8 kA;
    }
}
----

The upstream sweep is on by default: a pair that grades at the declared
fault is also checked above it, because characteristics converge as the
multiple rises. If it reports a failure above your fault, that is a
real finding.

An earth fault states its residual as well as its phase current, and
its `type` (one of `three_phase`, `two_phase`, `two_phase_earth`,
`single_phase_earth`):

[source,tc]
----
faults {
    F_EARTH { type = single_phase_earth; voltage = MV; I = 1.2 kA; residual = 1.2 kA; }
}
----

The upstream sweep stops at the largest fault the relays measure: the
largest residual for an earth pair, not the largest phase fault.

[#sequence]
== 6. Negative sequence

A 46 element has no default scaling, because the factor of three
between `I2` and `3I2` decides whether it operates at all. State which
the relay is set in:

[source,tc]
----
element 46 {
    function = neg_seq;
    measures = I2;         # or 3I2 -- read the report, do not assume
    curve    = definite;
    I_pickup = 200 A;
    t_delay  = 600 ms;
    views    = [SEQ];      # nothing to say on a phase sheet
}
----

An unbalanced fault behind a delta cannot be carried across by the
turns ratio, so state the figures at each level:

[source,tc]
----
scenario LV_2PH_MIN {
    type = two_phase;
    level LV { I = 12.4 kA; I1 = 7.16 kA; I2 = 7.16 kA; }
    level HV { I = 744 A;   I1 = 430 A;   I2 = 430 A;   residual = 0 A; }
}
----

[#times]
== 7. A required clearance time

A connection agreement, an arc-flash limit or a grid-code requirement
is a horizontal rule on the sheet, not a curve:

[source,tc]
----
times {
    T_BUS {
        name        = "33 kV bus clearance";
        t           = 200 ms;
        at_I        = 12.4 kA;
        description = "Connection agreement, primary protection";
    }
}
----

`at_I` says where along the rule to write its caption -- beside the
curve the requirement bites on. It does not restrict which sheets the
rule applies to; `views` does that. Requirements at the same time share
one rule and one caption.

An equipment rating or a load limit is the vertical counterpart -- a
current, not a time -- and goes in `currents`. `at_t` places its caption:

[source,tc]
----
currents {
    CABLE { name = "Cable rating"; I = 600 A; voltage = MV; at_t = 8 s; views = [F1_PHASE]; }
}
----

Style each kind of rule in its own page block, with the same keys:
`page { faults { ... } times { ... } currents { ... } }`, each taking
`style`, `color`, `width_px`, `labels`, `values`.

[#devices]
== 8. Fuses, cables and damage curves

Anything that is not a relay is a `device`. Give it the table the
manufacturer publishes:

[source,tc]
----
device F_100T {
    kind        = fuse;
    voltage     = MV;
    rating_I    = 100 A;
    min_melt    = [(200 A, 10.0 s), (400 A, 1.20 s), (800 A, 0.14 s)];
    total_clear = [(200 A, 16.0 s), (400 A, 2.00 s), (800 A, 0.26 s)];
}
----

A fuse grades on total-clear time as the primary and on minimum-melt as
the backup, automatically. It can be named in a `grade` like any relay.

A device takes `name` and `views` like a relay element, and joins a
chain by being listed in the group: `group AUX { members = [R_AUX, F_11A]; }`.
A fuse the report gives only a rating for has no curve to draw: say it is
missing rather than inventing one (its rating can go in `currents`).
If the fault current is past the table's last point, the tool holds the
last time and warns (`DEVICE_BEYOND_TABLE`) -- a finding to report.

[#sheets]
== 9. Several chains, several sheets

State each protection chain once, upstream first, and let the sheets
name a chain rather than listing curves:

[source,tc]
----
group FEEDER_1 { members = [R_INCOMER, R_FDR_1, R_RMU_1]; }
group FEEDER_2 { members = [R_INCOMER, R_FDR_2, R_RMU_2]; }

view F1_PHASE { group = FEEDER_1; quantity = phase; title = "Feeder 1"; }
view F2_PHASE { group = FEEDER_2; quantity = phase; title = "Feeder 2"; }
----

A relay in both chains is drawn on both sheets -- an incomer backs up
everything, so it belongs to every chain it is on.

*Scoping runs one way.* Every drawn item -- element, device, fault,
`times` entry, `currents` entry, point, annotation -- names its sheets
with `view = X` or `views = [X, Y]`; with neither it is on every sheet.
A view never lists or contains its items: `view { currents = [...] }`
and a `times { }` written inside a view are both errors.

Everything about a sheet's axes is on its view, not the page:

[source,tc]
----
view F1_PHASE {
    group = FEEDER_1; quantity = phase; voltage = MV;
    current_min = 50 A; current_max = 30 kA;   # omit to fit automatically
    time_min = 10 ms;   time_max = 10 s;
    tick_density = "normal";                  # sparse | normal | dense
}
----

[#placing]
=== Placing a relay between two others

When the report asks for the margin spread between a downstream and an
upstream relay, `grade` has a second shape. It solves the middle relay's
`tms` so its time at the fault sits `spacing` of the way from `below`
(faster) to `above` (slower), and checks both gaps against `margin`:

[source,tc]
----
grade {
    below = R_RMU:51; middle = R_FDR:51; above = R_INCOMER:51;
    fault = F_RMU_MIN; spacing = 50 %; margin = 0.30 s;
}
----

Use `primary` / `backup` or `below` / `middle` / `above`, never both in
one block. Only use this when the report asks for a setting to be
chosen; otherwise grade the pairs as the report set them.

[#marks]
== 10. Marking the sheet: points and annotations

A `point` is a coordinate -- inrush, a damage point -- a curve must
sit clear of. An `annotate` is a caption or a margin figure. Both take
a current as a `fault` does, or a *condition*: `fault = F_BUS;`, a
`scenario`, or a list for one annotation per condition. `annotate`
has three shapes:

[cols="1,3", options="header"]
|===
| Shape | Written

| A caption on one curve | `on_curve` + a current (`at_I` or a
  component), or `at_t` to read the curve at a time instead.
| A margin between two things | `primary` + `backup`, or `primary` +
  `point = "..."`. Vertical (time gap) unless `at_t` asks for current.
| A span, no curve at either end | `from` + `to`, both currents or both
  times -- a grading band, a supplier's range.
|===

`style` is `leader` (default, elbowed to a clear label), `pin`, or
`tag` (caption above, no leader). `label`, `color`, `coords` work as on
a `point`. Both take `view` / `views`, as `faults` do.

== Naming

Three tiers, answering three different questions. Use all three; they
cost one line each and they are what makes a sheet readable.

[cols="1,3", options="header"]
|===
| | Answers

| the *id* | How do I refer to this? A bare identifier -- `R_FDR_1`.
             Never displayed.
| `name` | What does the reader see? Free text, may contain spaces.
| `description` | What does it mean? Prose, for the legend and notes.
|===

Ids: `UPPER_SNAKE` for relays, faults and views; the IEEE C37.2 device
number for elements (`51`, `50`, `51G`, `46`, `67`). Both are
conventions rather than rules, but a study that follows them reads like
the report it came from.

== Presentation, and when to bother

Defaults are chosen to be right for an ordinary study. Reach for `page`
only when the sheet is going to be issued.

[source,tc]
----
meta {
    project  = "Riverside 33/11 kV";
    study    = "Feeder overcurrent grading";
    engineer = "A. Patel";
    date     = "2026-08-06";
    revision = "B";
}

page {
    size        = "A3";
    orientation = "landscape";
    border      = true;            # title block
    footer      = {
        left   = "[meta.project] · [meta.study]";
        center = "[meta.engineer] · rev [meta.revision]";
        right  = "[meta.date] · [page] of [of]";
    };
}
----

`[meta.*]` reads the `meta` block, so the footer stays correct when the
study is revised. `[page]` and `[of]` resolve when the study is
exported with every sheet in one PDF:

[source,bash]
----
tc-curves render study.ptc --pdf --all-views -o study.pdf
----

== What the validator will catch

Do not pre-empt these; write the study and let it tell you. But know
what they mean when they appear.

[cols="1,3", options="header"]
|===
| Finding | What it is telling you

| `TMS_MISSING` | You did not give a time multiplier and one is needed.
                  It has *not* been defaulted to 1.
| `UNKNOWN_SETTING` | A misspelled key. Refused rather than ignored,
                      because `tsm` for `tms` is a factor-of-ten error.
| `MEASURES_REQUIRED` | A sequence element with no stated scaling.
| `NO_OPERATION` | The element does not pick up at the fault given.
                   Usually a pickup above the fault current, or a
                   fault declared at the wrong voltage.
| `GRADE_BEYOND_CUTOFF` | You asked for a margin past where a curve
                          stops. Either the cutoff or the fault is wrong.
| `SEQUENCE_ACROSS_LEVELS` | A sequence current cannot be referred
                             across that transformer. Use a `scenario`.
| `COMBINE_LEVEL_AMBIGUOUS` | A `combine` draws on two voltage levels.
                              Add `voltage = <level>;` to say which bus
                              the envelope is read at.
| `SOLVE_SUPERSEDED` | Two grades solve the same relay, and the other
                       one demands more. Not an error: one relay has one
                       dial and the larger requirement governs. Report
                       which constraint set it.
| `SEQUENCE_RESIDUAL_CONFLICT` | You wrote both `I0` and `residual` and
                                 they disagree; the residual is three
                                 times `I0`. Copy whichever the report
                                 gives and delete the other.
| `FAULT_CURRENT_INVALID` | Usually a fault with no `I`: a range and
                            components are given as well as `I`, not instead.
| `GRADE_NOT_EVALUATED` | The grade has no `margin`, so no verdict.
| `NO_OPERATION` / `SPACING_UNRESOLVED` | A relay does not pick up at the
                            fault given -- often a pickup above it.
| `REFERRAL_NEEDS_CONNECTION` | An unbalanced fault is being carried
                                across a transformer whose windings do
                                not settle how. Declare the
                                `vector_group`, or use a `scenario`.
| `RENAMED_KEY`, `REMOVED_KEY` | An older form of the language. Run
                                 `tc-curves migrate study.ptc`; what it
                                 cannot rewrite, the message explains.
| `UNIT_MISSING` | A bare number. Every quantity states its unit, a
                   percentage included (`share = 50 %`).
| `VIEW_LISTS_ITEMS` | A view listing its items. Put `views = [..]` on
                       each item instead.
| `DELAY_ON_INVERSE` | `t_delay` on an inverse stage. Use `t_floor` for a
                       minimum time; an adder is not supported.
|===

A study that grades *fail* is not a broken study. It is the answer.
Report it as a finding, with the margin and the current it occurs at;
do not adjust settings to make it pass unless you were asked to.

== Checklist before you hand it over

. `tc-curves check study.ptc` exits `0`, or `3` with a grading failure
  you have reported in words -- and every warning it printed is either
  fixed or reported.
. `tc-curves report study.ptc` gives each grade a verdict, not
  "not evaluated".
. Every number in the study appears in the source report. Nothing was
  inferred to fill a gap.
. Every relay has `voltage`, and `ct_ratio` where the report gives it
  (it is required for settings in secondary amps; otherwise list it as
  missing rather than invent it).
. Every transformer the study grades across has its `vector_group`.
. Every element states `curve` and either `tms` or `t_delay`.
. Every number carries its unit: `A`, `kA`, `ms`, `s`, `kV`, `%`.
. Every item that belongs to some sheets only says so with `views`.
. Sequence and earth elements state what they measure.
. Each `grade` names a fault that exists at the primary's own voltage.
. Anything the report did not give is *named in your summary* as
  missing, rather than silently absent.
